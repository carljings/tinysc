# 贡献指南

## 开发原则

- 先写清可观察的失败或兼容目标，再做最小实现。
- 共享内核不得依赖 `javax.servlet` 或 `jakarta.servlet`。
- 1.x 生产代码不得引入 Jakarta Servlet；Java class major 必须不高于 52。
- 不为单个业务项目添加项目名判断、硬编码路径或专属兼容分支。
- 行为、兼容范围、配置或运维方式变化时，同步测试与 `docs/`。

## 提交流程

1. 从目标维护线创建短分支；1.x 修复以 `1.x` 为基线，2.x 功能以 `main` 为基线。
2. 添加能失败的单元、Probe WAR 或差分案例。
3. 在真实 JDK 8 上运行 `mvn clean verify`。
4. 检查 kernel namespace、发行 class major、文档和变更记录。
5. 提交说明应包含问题、取舍、验证命令、结果和未覆盖风险。

容器语义变更需要同时说明与 Servlet 3.1/Tomcat 8 的差异。性能改动必须附同机同参原始结果，
不能只提交最好的一次测量。

## 贡献授权

项目采用 [Apache License 2.0](../LICENSE)。除非提交者明确书面标注为 `Not a Contribution`，
有意提交给 TinySC 的贡献按 Apache License 2.0 第 5 节授权，不附加额外条款。提交者必须有权
提供相关代码、文档和测试数据；不得提交第三方私有源码、业务数据或凭据。

## 代码与测试位置

- 所有实现、测试和开发工具位于 `src/`。
- 所有说明、ADR、验收和基准报告位于 `docs/`。
- 生成物只进入 Maven `target/` 或已忽略的运行目录。
- 业务项目只作为只读验收夹具，不复制其源码、配置或凭据到本仓库。

## 行为准则

讨论应围绕可复现证据和技术取舍，尊重不同背景的贡献者。骚扰、歧视、泄露他人凭据或未经
授权发布业务数据不可接受。安全问题应按 [security.md](security.md) 的非公开流程报告。
