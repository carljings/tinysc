# 产品定位：面向单 WAR，比 Tomcat 更专注

tinysc 的“先进”不是功能数量超过 Tomcat，而是针对一个明确场景做更少的工作：一个进程只运行
一个 WAR。Tomcat 的多 Host、多应用、JSP、AJP、Manager、热部署和集群能力仍有价值；tinysc
主动不携带这些通用能力，以换取更短的启动链、更少的常驻组件和更清晰的故障边界。

## 可形成差异的设计

| 设计 | 用户价值 | 当前证据 |
|---|---|---|
| 单进程单 WAR | 没有 Engine/Host/多 Context 调度树和目录轮询 | 已由架构与启动器落实 |
| 事务式启动 | 应用初始化失败时不开放 HTTP 端口，不把端口监听冒充应用就绪 | 两个真实 WAR 的数据库失败测试已验证 |
| SHA-256 展开缓存 | 同一 WAR 重启不重复解压，适合开发、测试和容器重建 | 已实现并有部署测试 |
| 2 条默认 I/O 线程 + 有界 worker | 降低单应用常驻线程，过载快速 503 | 已实现；Probe 预备基准线程数 59 对 64 |
| namespace 检查 | 在替换容器前识别 javax/jakarta 代际，减少错误升级 | 已实现 `tinysc inspect` |
| 中立内核 | 1.x/2.x 共享请求交换和生命周期，不把 namespace 扩散到核心 | Maven 门禁禁止内核依赖 Servlet API |
| 精简发行面 | 基础包不带 JSP、AJP、Manager、多 Host 和自动热部署 | 1.x 当前结构已落实 |

## 当前可以说什么

- tinysc 是面向单 WAR 的轻量容器，而不是 Tomcat 的全功能复刻。
- Probe WAR 的首轮同机数据表明，tinysc 的应用就绪中位数比 Tomcat 8.5.100 快 41.4%，
  线程和文件描述符也更少。
- 相同短请求夹具下吞吐中位数略高，但测试时长太短，仍只是优化方向，不是发布声明。
- 真实 WAR 初始化失败时，tinysc 能保留业务根因并拒绝开放流量。

## 当前不能说什么

- 不能笼统宣称所有业务的内存都低 30%；预备基准只低 12.6%，尚未达到门槛。
- 不能笼统宣称尾延迟优于 Tomcat；预备基准 p99 为 4ms 对 3ms，当前未达标。
- 不能把两个内部 Legacy WAR 表述为已启动成功；它们都在业务数据库初始化阶段失败，
  尚未开放端口，也没有完成页面访问。
- 不能把 Tomcat 8.5.100 当作仍受官方安全维护的版本；它只是遗留项目对照基线。
