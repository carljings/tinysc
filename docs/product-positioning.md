# 产品定位：面向单 WAR，比 Tomcat 更专注

tinysc 的“先进”不是功能数量超过 Tomcat，而是针对一个明确场景做更少的工作：一个进程只运行
一个 WAR。Tomcat 的多 Host、多应用、JSP、AJP、Manager、热部署和集群能力仍有价值；tinysc
主动不携带这些通用能力，以换取更短的启动链、更少的常驻组件和更清晰的故障边界。

## 可形成差异的设计

| 设计 | 用户价值 | 当前证据 |
|---|---|---|
| 单进程单 WAR | 没有 Engine/Host/多 Context 调度树和目录轮询 | 已由架构与启动器落实 |
| 事务式启动 | 应用初始化失败时不开放 HTTP 端口，不把端口监听冒充应用就绪 | 两个真实 WAR 的数据库失败测试已验证 |
| SHA-256 展开缓存 | 同一 WAR 重启不重复解压，适合开发、测试和容器重建 | 已实现并有部署测试 |
| 默认 `min(4, CPU)` 条 I/O 线程 + 有界 worker | 控制单应用常驻线程，减少多核环境 HTTP 解码和响应写回竞争，过载快速 503 | 已实现；最终候选已通过当前并发切换门禁 |
| 短请求低开销路径 | zero-byte request 跳过 0 字节 byte-budget CAS 与 `tryReserve(0)` 锁；access log 对常见安全字段整体追加 | 已实现；保留请求计数、raw reservation lease 与日志清洗语义 |
| 条件静态资源 | 文件系统和 Resource JAR 的 GET/HEAD 支持 `If-Modified-Since` / `304`，静态 POST 仍返回资源体 | 已实现并有回归测试 |
| namespace 检查 | 在替换容器前识别 javax/jakarta 代际，减少错误升级 | 已实现 `tinysc inspect` |
| 中立内核 | 1.x/2.x 共享请求交换和生命周期，不把 namespace 扩散到核心 | Maven 门禁禁止内核依赖 Servlet API |
| 精简发行面 | 基础包不带 JSP、AJP、Manager、多 Host 和自动热部署 | 1.x 当前结构已落实 |

## 当前可以说什么

- tinysc 是面向单 WAR 的轻量容器，而不是 Tomcat 的全功能复刻。
- 最终候选在 Java 8 `clean verify` 的 157 项测试中全绿；Probe WAR 的并发 32/128 五轮交替均为
  0 失败，吞吐分别达到 Tomcat 的 93.77% 和 91.01%，满足当前可回滚切换的 90% 安全门槛。
- 真实 WAR 初始化失败时，tinysc 能保留业务根因并拒绝开放流量；Legacy WAR B 已在认证后完成
  两轮关键路径 L2 验收，其授权切换已通过但带有资源漂移证据保留项。

## 当前不能说什么

- 不能宣称 RSS 比 Tomcat 低 30%；最终并发 32/128 中位数分别为 199,280 / 206,160 KB 和
  196,528 / 216,368 KB，尚未达到 1.0 门槛。
- 不能宣称吞吐不低于或优于 Tomcat；最终比值为 93.77% 和 91.01%，只达到当前切换安全下限。
- 不能笼统宣称尾延迟优于 Tomcat；最终 p99 在并发 32 下为 1ms / 0ms，在并发 128 下为
  2ms / 2ms。
- 不能把 Legacy WAR B 的关键路径 L2 表述为完整业务兼容；上传、错误页、全部管理动作和长事务等
  L3 范围仍未覆盖。Legacy WAR A 仍在业务数据库初始化阶段失败。
- 不能据 Legacy WAR B 宣称真实业务广义更快；其认证后 `page_load` 仍约 1.36–3.03s，冷启动
  183,945ms，主要由 Spring 与数据库初始化主导。
- 不能把 10 分钟 soak 写成完整长稳通过；线程/FD 漂移汇总证据不完整，1 小时/24 小时长稳仍未执行。
- 不能把 Tomcat 8.5.100 当作仍受官方安全维护的版本；它只是遗留项目对照基线。
