# ADR-0008：用可复现基准兑现性能亮点

## 状态

Accepted

## 背景

tinysc 需要相对 Tomcat 突出更少资源、更高并发和更快开发测试启动，但基础软件的性能声明
如果没有公平口径，很容易被应用初始化、JVM 参数或挑选样本误导。

## 决策

将低资源、并发稳定性和快速启动设为 1.0 发布门禁。采用同机、同 JDK、同 WAR、同资源上限、
多次重复的 Tomcat 对照；分别测 container ready、deployment ready 和 application ready。
所有正式声明必须链接到原始命令和结果。

架构上优先采用单 WAR、按需模块、有界队列、I/O 与应用线程隔离、安全展开缓存、元数据缓存和
exploded directory 快速开发路径。

## 后果

### 正面

- 产品亮点可验证、可回归，不依赖主观描述。
- 性能回退能在发布前发现。
- 容器开销和业务外部依赖时间得到区分。

### 负面

- 需要维护基准环境和原始结果。
- 某些优化必须让位于 Servlet 正确性与安全校验。
- 在真实数据出来前不能使用绝对性能宣传语。

### 中性

性能门槛可通过新的 ADR 调整，但历史结果和调整原因必须保留。

## 备选方案

只以微基准比较单个 parser：拒绝，因为不能代表完整请求链。只比较一次最快启动：拒绝，因为
结果不可重复。使用不同 JVM 参数比较：拒绝，因为无法归因于容器设计。
